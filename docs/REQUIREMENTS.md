# Требования

Этот файл описывает, **что** должен представлять собой сайт: поведение, дизайн, контент. Как это реализовано — в `docs/IMPLEMENTATION.md`. При расхождении требований и реализации правильными считаются требования.

## 1. Общее

- Название: **Gnozila**.
- Разделы: **Playground**, **Articles**, **Links**.
- Стартовая страница: Playground (`/` переводит на `/playground/`).
- Логотип в шапке — инлайновый SVG; favicon — `public/favicon.svg`.
- **Язык интерфейса — английский** (навигация, футер, подсказки, 404, ошибки). **Язык контента — русский** (проекты, статьи, ссылки).
- Корневой `<html lang="ru">` (основной текст русский); английские элементы интерфейса помечаются `lang="en"`.
- `title` и `description` — любые печатные символы Unicode. Ограничения безопасных символов — только для `slug` и `tags` (латиница `a-z0-9-`; теги в URL только латиницей — осознанный компромисс).
- **Сайт полностью статический** — набор готовых файлов на GitHub Pages, серверной логики нет.
- **Основа — десктоп.** Playground и Articles ведут себя как приложения: шапка и левая колонка всегда на месте, меняется только правая область. Мобильная версия — по остаточному принципу (сайт открывается и читается, полный функционал не гарантируется).

## 2. Дизайн

- **Тёмная тема по умолчанию** (`color-scheme: dark`) и **светлая тема** (переключатель в шапке, `data-theme` на `<html>`). Палитра — «пепельная» (нейтрально-серые тона).
- **Свечение запрещено:** без `text-shadow`/glow (правило для автора, автопроверки нет).
- Шрифты — системные; внешних запросов к CDN и Google Fonts нет.
- Цвета задаются ролями (токены в `globals.css`): фон, текст, приглушённый, граница, акцент, фон кода, четыре цвета callouts, неровный фон (`--surface-*`), глубокий фон сцен (`--surface-deep`: тёмнее `--bg` в тёмной теме, слегка серый в светлой), `--logo-*`. В остальных местах литералы цветов/размеров не пишутся.
- **Проекты Playground следуют теме сайта.** Оформление проекта по возможности использует токены (`--bg`, `--fg`, `--muted`, `--border`, `--accent`, `--code-bg`, `--space-*`, `--radius`, `--font-*`) и переключается вместе с темой сайта без перезагрузки. DOM/SVG-проекты берут токены из CSS; canvas-проекты читают значения токенов через `getComputedStyle` и перерисовываются при смене `data-theme`.
- **Исключения.** Собственная палитра допустима, если она — часть замысла (арт-визуализация, эмулятор терминала, симулятор прибора) или проект — самодостаточное legacy-приложение в iframe. Фиксированной может быть только содержательная часть; подписи, подсказки, панели управления и прочая обвязка используют токены сайта и остаются читаемыми в обеих темах.
- `:focus-visible` у всех интерактивных элементов.
- `:hover` работает только на устройствах с мышью (`@media (hover: hover)`).
- Пункты навигации, элементы списков и кнопка `← Back` — область касания ≥ 44px по высоте.
- В списках под названием — `description` мелким приглушённым шрифтом (~0.8125rem), ≤ 2 строки; название и описание — одна ссылка. Всплывающих подсказок нет.

## 3. Раскладка и прокрутка

- **Десктоп (≥ 768px):** шапка сверху; слева колонка (теги + список + футер, sticky), справа — область раздела.
- **Мобильные (< 768px):** схема «список → деталь»: на списке — только список, на детали — только деталь + `← Back`. Футер — внизу экрана: при коротком списке прижат к нижнему краю, при длинном оказывается в конце страницы.
- Правая область Playground занимает высоту окна под шапкой и не прокручивается; проекты прокручивают себя сами.
- Статьи прокручиваются обычным окном.

## 4. Страницы

- **Playground** (`/playground/`, `/playground/<slug>/`): слева список проектов, справа — проект. Пустое состояние — «Select a project».
- **Articles** (`/articles/`, `/articles/<slug>/`): аналогично, справа — статья. Пустое состояние — «Select an article».
- **Links** (`/links/`): список ссылок.
- **404** — страница с сообщением и ссылкой на Playground.
- **Ошибки** — `error.tsx`/`global-error.tsx` с кнопкой повтора.

## 5. Контент

- Поля записи: `slug`, `title`, `description`, `createDate`, `updateDate` (формат `YYYY-MM-DD`, `updateDate ≥ createDate`), `tags` (≥ 1, латиница `a-z0-9-`).
- Проекты — в `content/projects.ts`, статьи — в `content/articles.meta.ts`, ссылки — в `content/links.ts`, виджеты статей — в `content/widgets.ts`. Порядок проектов — по важности.
- Теги проектов — `gallery`, `sim`, `other`, `test`; у статьи — `experiment`.
- `slug` не менять после публикации (ломаются URL).

## 6. Формат статей

- Статьи — Markdown (`.md`), совместимы с Obsidian.
- Запрещено: frontmatter, заголовок `#` (h1), HTML, `[[wikilinks]]`.
- Медиа — только `/media_articles/<имя>` (картинки/видео/аудио; файлы в `public/media_articles/`).
- Встраивание проекта или виджета — блок ```` ```project slug=<slug> height=<px> ````.
- Математика — KaTeX (`$…$` и `$$…$$`); диаграммы — Mermaid; код — с подсветкой.

## 7. SEO

- Каждая страница: `<title>`, `<meta name="description">`, canonical (адрес со слешем на конце), Open Graph (`og:title`, `og:description`, `og:image`), Twitter card.
- `sitemap.xml` и `robots.txt` — статические.
- Статьи: `article:published_time` (createDate) и `article:modified_time` (updateDate).

## 8. Платформа

- Хостинг **GitHub Pages**; публикация автоматическая при изменении `main`.
- Все канонические адреса заканчиваются на `/`.
- Несуществующий адрес → 404 (статус 404).
- Лимиты GitHub Pages: сайт ≤ 1 ГБ, файл ≤ 100 МБ (в проекте жёстче: файл > 50 МБ — ошибка сборки).
- Данные проектов — рядом с кодом или в `public/`; собственного сервера нет. Внешние сервисы — только fetch из браузера, проект обязан обработать недоступность.
- Если понадобится серверная логика (формы, авторизация, БД) — другой хостинг и смена режима сборки; структура проекта сохраняется.

### Осознанно не входит

Поиск по сайту, RSS, комментарии, отображение дат, PWA, серверные функции, индивидуальные превью для соцсетей.
